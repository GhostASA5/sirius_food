# Сириус.Еда

Учебный FastAPI-проект восстановлен из приложения А лабораторной работы № 2. История Git содержит отдельные коммиты для лабораторной № 2 и практической № 3.

## Лабораторная работа № 2

Модули `orders` и `users` разделены на `router.py`, `service.py` и `repository.py`. Запрос проходит через роутер, сервис и репозиторий к PostgreSQL. Сервис получает репозиторий через конструктор и не импортирует FastAPI или SQLAlchemy. Создание заказа и списание баланса выполняются в одной транзакции. Маршруты, структуры ответов и коды ошибок MVP были сохранены в коммите лабораторной работы.

## Практическая работа № 3

Регистрация сохраняет bcrypt-хеш пароля и назначает роль `student`. `/auth/login` выдаёт access-токен на 15 минут и refresh-токен на 7 дней. Хеш refresh-токена хранится в БД, `/auth/refresh` выдаёт новый access-токен после проверки записи. JWT содержит тип токена, поэтому refresh-токен нельзя использовать для доступа к заказам.

Для входа в защищённый маршрут клиент передаёт `Authorization: Bearer <access_token>`. `get_current_user` проверяет подпись, срок действия, тип токена, существование пользователя и блокировку. `require_role` проверяет роль в API-слое. Сервисы заказов, пользователей и доставок проверяют право на конкретный объект. Отсутствующий токен даёт 401, чужая роль или объект — 403.

`POST /orders/create` берёт пользователя из JWT; `user_id` отсутствует в теле запроса. `POST /orders/{order_id}/cancel` доступен владельцу заказа, `GET /orders/kitchen/orders` — повару. Изменение меню доступно администратору и повару. `GET /delivery/mine` показывает курьеру только его доставки; `GET /delivery/{delivery_id}` доступен назначенному курьеру, владельцу заказа и администратору. Назначение курьера доступно администратору, завершение доставки — назначенному курьеру. Пополнение баланса доступно только владельцу. Регистрация остаётся публичной, чтобы новый пользователь мог получить учётную запись.

## Запуск

Из каталога `sirius_food`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Замените SECRET_KEY случайной строкой длиной не менее 32 символов.
docker compose up -d db
alembic upgrade head
uvicorn app.main:app --reload
```

Swagger доступен по http://127.0.0.1:8000/docs при `DEBUG=true`. В конфигурации без режима отладки документация отключена. `.env` исключён из Git.

Если база создана запуском версии лабораторной № 2 и уже содержит таблицы MVP, отметьте применённую исходную схему командой `alembic stamp 0001_mvp`, затем выполните `alembic upgrade head`. Перед этим сохраните резервную копию БД. Для существующих пользователей миграция оставляет `password_hash` пустым, поскольку исходные пароли неизвестны. Пароль и роль задаются локальной командой администратора:

```bash
python -m scripts.manage_users student@example.com --set-password
python -m scripts.manage_users cook@example.com --role cook
python -m scripts.manage_users courier@example.com --role courier
python -m scripts.manage_users admin@example.com --role admin
```

Перед назначением роли пользователь должен зарегистрироваться. Команда запрашивает новый пароль без вывода на экран.

## Проверка

```bash
pytest -q
```

Тесты сервисов не требуют СУБД. HTTP-тесты используют SQLite в памяти и проверяют отсутствие токена, чужую роль, чужой заказ и доставку, хеширование и тип JWT. CI запускает `pytest` на Python 3.12. Бонусные задания с Redis rate limiting, CORS и rotation refresh-токенов не включены.
