# ADR 002 Начисление и компенсация баллов

## Контекст

В проекте денежный баланс уменьшается при создании заказа. Маршрут оплаты переводит заказ в `paid` и записывает `OrderPaid` в Outbox. Отмена возможна через HTTP и через обработчик сбоя доставки.

## Решение

Промокод уменьшает денежный резерв при создании заказа. Списание баллов, возврат соответствующей части денежного резерва и переход в `paid` выполняются в одной транзакции. Строка пользователя сериализует изменения кошелька и счёта лояльности, строка промокода защищает общий лимит и проверку повторного использования, строка заказа защищает переходы состояния.

Начисление обрабатывает `OrderPaid`. При отмене общая операция возвращает денежную часть и создаёт `OrderCancelled` в Outbox. Независимые потребители возвращают баллы и восстанавливают промокод. Уникальные ключи по заказу позволяют повторять обработку после сбоя. Если отмена предшествует обработке `OrderPaid`, начисление пропускается по состоянию заказа.

## Последствия

Баллы и повторная доступность промокода после отмены обновляются асинхронно. Создание заказа по-прежнему требует денежных средств на заказ после скидки. Выбран Celery Beat для фоновой деактивации, чтобы истёкшие записи меняли состояние в БД. Синхронная проверка срока не допускает использования кода между запусками задачи.
