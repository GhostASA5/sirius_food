# ADR 001 Elasticsearch для поиска по меню

Дата: 12 ноября 2026 года. Статус: принято для учебного проекта.

## Контекст

Поиск должен учитывать русские словоформы, опечатки, вес полей, категории, цены, автодополнение и фасеты. PostgreSQL остаётся источником данных меню. SQL LIKE не учитывает морфологию и релевантность; PostgreSQL Full Text Search поддерживает словари и ранжирование, но автодополнение и фасеты потребовали бы дополнительных индексов и запросов.

## Решение

Использовать Elasticsearch как отдельный поисковый индекс. Название и описание индексируются русским анализатором. Для подсказок применяется edge_ngram. Точное совпадение названия получает наибольший вес, затем фразовое совпадение; название важнее описания. Меню меняется в PostgreSQL, событие `menu.item.changed` записывается в outbox в той же транзакции и через RabbitMQ поступает поисковому обработчику. Повторное событие безопасно: документ индексируется по постоянному ID блюда. При первом запуске и вручную индекс пересобирается из PostgreSQL.

## Последствия

Поиск зависит от Elasticsearch и при его недоступности отвечает 503; создание и изменение блюд сохраняются в PostgreSQL, а outbox позволяет повторить синхронизацию. Индекс обновляется с небольшой задержкой. Elasticsearch требует дополнительной памяти и обслуживания. На имеющихся двух исходных блюдах PostgreSQL LIKE оказался быстрее, поэтому этот замер не доказывает преимущество Elasticsearch по задержке. Выбор обусловлен функциями полнотекстового поиска, а не результатом малого тестового набора.
